# ADR-004: Bronze is append-only, loaded incrementally by PySpark

- **Decision:** bronze tables keep every record as received and are never updated. They are loaded by Auto Loader (`cloudFiles`) with `trigger(availableNow=True)`: each run loads all files not seen before, then stops. Auto Loader's checkpoints and schema files live in their own volume, `corvella.landing._checkpoints`, separate from the inbox. Each row carries load metadata: the source file path, the arrival date from the folder name, and the ingestion timestamp. Bronze tables are not partitioned at this size; if reads by ingestion date get slow, liquid clustering on that column is added instead.
- **Context:** the audit constraint needs traceability back to the source, and corrections arrive as new records, not overwrites. Free Edition runs only on serverless compute, which supports only the AvailableNow (and deprecated Once) streaming triggers, not continuous or processing-time triggers ([serverless limitations](https://docs.databricks.com/aws/en/compute/serverless/limitations)). AvailableNow matches the hourly and daily batch runs. Community reports show a location-overlap error when checkpoints share UC-managed storage with the source files; a separate volume avoids it.
- **Alternatives considered:** updating bronze with COPY INTO (also incremental and idempotent, kept as the fallback if Auto Loader's checkpoints can't be made to work); continuous streaming (not supported on serverless, and not needed); partitioning by ingestion date (adds many small files at this volume).
- **Consequences:** bronze grows continuously; deduplication and the current state of each record are handled in silver. The checkpoint setup must be tested on the first day of ingestion work.
